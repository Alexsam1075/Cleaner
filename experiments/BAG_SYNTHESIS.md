# Синтетические пакеты

`bag_scenes.py` генерирует процедурную сетку пакета и применяет существующий CPU-рендерер `cleaner_view`. Цветной кадр, карта глубины и карта объектов принадлежат одной позе камеры. Рядом хранятся сетка и `scene.json` с физическими параметрами.

Из корня проекта:

```powershell
python sim/bag_scenes.py --out sim/bag_data --split train --count 10 --poses 3 --scale 0.5
python sim/bag_scenes.py --out sim/bag_data --split val --count 2 --poses 3 --scale 0.5
```

Для повторного запуска с новыми сценами используйте `--start 10` и т. п. Готовые папки не перезаписываются. `--mesh-only` создаёт сетку и описание без кадров. `--renderer blender` выбирает существующий Blender-рендерер и требует переменную `BLENDER` с путём к установленному исполняемому файлу; на Aion Lab Blender при проверке отсутствовал.

В `train` используются чётные процедурные seed, в `val` — нечётные, поэтому меши между этими группами не совпадают. Каждый экземпляр имеет отдельный `id`; кадры его поз должны оставаться в одной группе при обучении и проверке.

Для собственного рендера `f_*/color.png` — RGB, `depth.png` — осевая глубина uint16 в миллиметрах, `index.png` — идентификатор объекта 1. `sim/run_blender.py:read_frame` читает этот формат и прежние EXR Blender, преобразуя глубину в метры. `SimFrames` обнаруживает сцены в соответствующей директории `scene_*`.

Масса граммах = `film_area_m2 * thickness_um * polymer_density_g_cm3`; исходная площадь включает две стороны. Сетка — процедурно согнутая поверхность, а не симуляция ткани, и поверхность может самопересекаться. Для толщины и плотности задаются искусственные диапазоны, содержимое и ручки отдельно не моделируются. `volume_ml` в сцене — объём ограничивающего прямоугольника, то есть **приближение оболочки**, а `film_volume_ml` — объём плёнки. Их нельзя считать проверенной разметкой объёма реального пакета. Не использовать synthetic-only метрики как доказательство качества на фотографиях; нужна проверка по реальным предметам с отложенными `object_id`.
