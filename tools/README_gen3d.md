# gen3d — 3D-генератор кадров для Astramis

Берёт настоящие объекты из `real/train`, строит их облако точек в координатах пола
и переносит на пустой пол другого кадра: поворот вокруг вертикали (±35°), отражение,
сдвиг, масштаб, z-буфер (честные перекрытия), мягкая тень. Дыры в глубине у стекла и
металла переезжают вместе с объектом. Объём и масса пересчитываются как ×s³, take — по массе.
`object_id` сохраняется, поэтому при валидации по предметам утечки нет. Тест не читается.

```
python tools/gen3d.py --data dataset --out dataset/gen3d --n 1000 --seed 0
python tools/gen3d.py ... --scale 1,1 --no-photometric      # без масштаба и перекраски
python tools/gen3d.py ... --exclude-objects b06,s45         # не брать эти предметы
```
Результат: `dataset/gen3d/<id>/{color,depth,mask}.png, meta.json` и `dataset/labels/gen3d_train.json`
(формат как у synth_train.json). Скорость ≈ 1 кадр/с на ядро, нужны только numpy и opencv.

## Что проверено (20.11, валидация по предметам, 5 фолдов × 3 сида, только реальные кадры)

Табличные модели (материал — случайный лес на цвете/текстуре/дырах; объём — поправка по классу; решение — масса с порогом 250 г):

| Обучение | M | V | S |
|---|---|---|---|
| real + synth (организаторы) | **0.506** | **0.591** | **0.673** |
| + 2469 объектов gen3d (масштаб 0.75–1.3, перекраска) | 0.464 | 0.539 | 0.601 |
| + 300 из них | 0.481 | 0.574 | 0.630 |
| + 829 объектов gen3d без масштаба и перекраски | 0.492 | 0.568 | 0.656 |

Вывод: для признаков материала/объёма/решения gen3d **не помогает** (при повороте камера видит
«скорлупу» объекта с другой стороны, и сырой объём считается иначе, чем на реальных кадрах).
Не проверено: детектор и CNN-классификатор (нужна GPU). Использовать только если на общем сплите
по `object_id` через score.py это даёт прирост D или M.
