# nav.py — маршрут объезда для SurfexUnit

По одному кадру камеры глубины строит маршрут робота: лёгкое забрать, тяжёлое и незнакомое объехать.

## Как работает

1. **Карта пола сверху** (сетка 1 см) из `depth.png` и `floor_plane` из `meta.json`: где пол виден,
   где что-то возвышается, где пол закрыт (тень за предметом, край обзора).
2. **Тело робота в кадре не считается препятствием.** Чёрный корпус слева внизу и боковая щётка
   справа есть на каждом кадре. Статическая карта по сериям съёмки лежит в `nav_self_masks/`
   (доля обучающих кадров, где пиксель без глубины или выше пола; по тесту не считалась),
   плюс правило: всё, что касается нижнего края кадра у боков, — робот.
3. **Три вида объектов:**
   - `ЗАБРАТЬ` — take=1: робот проезжает объект по центру, конвейер забирает;
   - `ОБЪЕХАТЬ` — take=0 (тяжелее 500 г): препятствие, раздувается на полширины робота + запас;
   - `НЕИЗВЕСТНО` — то, что модель не узнала: выступ выше 2,5 см или большая область без глубины
     (чёрные, прозрачные, слишком близкие предметы). Тоже объезд — безопасное поведение по умолчанию.
4. **Маршрут** — поиск кратчайшего пути по сетке: старт у носа робота → по очереди через все цели
   «забрать» (по удалённости) → дальний край обзора. Невидимый пол проходим, но дорого;
   невидимый пол рядом с препятствием, уходящим за край кадра, закрыт. Нет пути → «стоп, позвать оператора».
5. Для каждой цели считается, какую долю её площади накрывает полоса робота (`covered_by_robot`);
   меньше 60% — статус «недобор». Если полоса задевает препятствие — «ВНИМАНИЕ».

## Запуск

```
# по разметке (маски и take из json)
python tools/nav.py --data dataset --frames real/train/r_0041 --labels dataset/labels/real_train.json --out nav_out

# по ответу модели в формате кейса (рамки + take) — например, submission.csv Саши
python tools/nav.py --data dataset --frames-glob "real/test/*" --submission submission.csv --out nav_out

# без модели: всё, что торчит над полом, — препятствие
python tools/nav.py --data dataset --frames real/test/r_0008 --out nav_out
```

Параметры: `--robot-width 0.40` (м), `--margin 0.05` (м), `--avoid-mass-g` (г, режим осторожности),
`--gt-labels` (истинная разметка для проверки качества объезда). Нужны numpy и opencv-python; Pillow — для русских подписей.

На выходе: `<кадр>_nav.jpg` (слева кадр с полосой пути и решениями, справа карта сверху: серый — видимый пол,
тёмный — не видно, красный — объехать, оранжевый — неизвестно, зелёный — забрать, розовый — запретная зона
для центра робота, синий — путь) и `nav_report.json` (статус, путь в координатах пола в метрах,
решение и статус по каждому объекту). Около 0,5 с на кадр на CPU.

## Режим осторожности и связь с объёмом/материалом

Решение «забрать/объехать» модуль берёт из `submission.csv`, поэтому любое улучшение объёма или материала
у модели сразу улучшает объезд: масса = объём × плотность (по материалу), take = масса ≤ 500 г.
Метрика кейса S одинаково штрафует обе ошибки, а для робота наезд на тяжёлое опаснее, чем пропущенный лёгкий.

`--avoid-mass-g N` — объезжать всё, у чего оценка массы > N г, даже если take=1 (take=0 объезжается всегда).

`--gt-labels` — проверка по разметке: доля задетых тяжёлых (полоса робота накрыла > 5% пятна) и убранных лёгких
(накрыто ≥ 60%), число остановок. Итог в `nav_eval.json`. Так коллеги видят, как их изменения объёма и материала
отражаются на безопасности объезда:

```
python tools/nav.py --data dataset --frames-glob "real/train/*" --submission val_pred.csv \
    --gt-labels dataset/labels/real_train.json --avoid-mass-g 350 --out nav_eval
```

Проверка на 90 сценах gen3d (144 объекта: 19 тяжёлых, 125 лёгких). В ответ подставлена масса с ошибкой
в среднем ~1,8 раза (лог-нормальный шум σ=0,6) — 3 повтора шума:

| Режим | Тяжёлых задето | Лёгких убрано | Остановок |
|---|---|---|---|
| точные массы (потолок) | 0% | 91% | 6% |
| по take (порог 500 г) | 19% | 87% | 4% |
| `--avoid-mass-g 350` | 9% | 77% | 6% |
| `--avoid-mass-g 250` | 2% | 69% | 7% |

Вывод: при ошибке массы ~1,8 раза запас 350 г вдвое снижает наезды ценой ~10% неубранного лёгкого.
Чем точнее объём и материал у модели, тем меньше нужен запас.

## Проверка (21.11)

- Реальные кадры с тяжёлыми объектами (металл 1 кг, пластик 0,55–1 кг): объезд или честный стоп,
  когда объект перекрывает весь видимый проход для робота шириной 40 см (r_0017).
- 14 сгенерированных сцен с 1–3 объектами (gen3d): все лёгкие цели накрыты на 87–100%,
  ни одного касания препятствий; режим `--submission` по рамкам даёт то же.

## Ограничения

- Ширина робота не указана в кейсе: по кадрам корпус и щётка стоят примерно на ±0,2 м, взято 0,40 м.
- Объезд только по одному кадру: что за краем обзора, робот не знает; на реальной машине карту надо
  накапливать по ходу движения (одометрия + те же шаги на каждом кадре).
- Высота объекта для конвейера не учитывается: высокий лёгкий предмет тоже «забрать».
