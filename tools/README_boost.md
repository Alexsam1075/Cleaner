# Как поднять счёт с 79: что проверено и что запускать

Срез: 21.11, публичный лидерборд — 79.

## Почему локально 83–87, а на сайте 79

Тестовые кадры — блоки между обучающими по времени съёмки. **В тесте много предметов, которых нет в обучении**
(коробка r_0025–29, канистра r_0038–40, пластина r_0021–24). Если локальная проверка делит кадры случайно,
модель видит тот же предмет в соседнем кадре, и оценка завышена. Честная проверка — по `object_id`
(отложенные предметы целиком). Сравнивать улучшения можно только так.

## Что проверено и не помогает

**Склейка соседних кадров в серии** (голосование материала, медиана объёма внутри серии) — `0` или минус.
Проверено на real/train с честными OOF-предсказаниями: даже при идеальной группировке по `object_id`
M 0.404 → 0.361, V 0.588 → 0.596. Модель ошибается на предмете целиком, а не на отдельных кадрах,
поэтому голосование ошибку не исправляет. Не тратить время.

**Табличная поправка объёма** (ExtraTrees/бустинг поверх геометрии из глубины) упирается в V ≈ 0.57–0.59
при точных рамках; разные модели и смеси дают ±0.01. Большой прирост V здесь не лежит.

## Что запускать на сервере

### 1. Материал на DINOv2 — `tools/material_dino.py`

Замороженный DINOv2 + логистическая регрессия по вырезке объекта (плотная рамка и рамка с контекстом, TTA-зеркало).
Голова учится на real+synth, проверка — по `object_id`.

```bash
pip install torch torchvision scikit-learn   # если нет
python tools/material_dino.py cv --data dataset --out mat_dino               # печатает M для разных C, ±synth
python tools/material_dino.py cv --data dataset --out mat_dino --backbone dinov2_vitl14   # попробовать большую
python tools/material_dino.py apply --data dataset --out mat_dino \
       --submission submission.csv --out-csv submission_mat.csv               # переписать материал в сабмите
```
Сравнить напечатанное M с текущим M модели на тех же отложенных объектах. Применять, только если выше.
`apply` берёт лучшие настройки из `mat_dino/best.json`. Признаки кэшируются, второй запуск — минуты.

### 2. Ансамбль моделей фолдов — `tools/fuse_subs.py`

Weighted Boxes Fusion по нескольким сабмитам: модели 5 фолдов, прогоны с `augment=True` (TTA), разные imgsz.
Рамки сливаются, score усредняется по моделям (одиночные ложные срабатывания проседают),
форма/материал — голосование, объём — среднее в логарифме.

```bash
python tools/fuse_subs.py --subs sub_fold1.csv sub_fold2.csv sub_fold3.csv sub_fold4.csv sub_fold5.csv \
       --take-volume-ml 429 --out submission_fused.csv
```
Проверка на шумных копиях разметки: три сабмита по 57–62 → слитый 77.9 (D 0.89, M 0.77, V 0.63).
У настоящих моделей ошибки похожи, поэтому реальный прирост меньше; ожидаемо +1–3 балла.
Проверять так: OOF-сабмиты на отложенных кадрах → `fuse_subs.py` → `python score.py check ...`.

### 3. Детекция (D, вес 0.40)

- Обучение с `imgsz=1280`, сильнее аугментации (`copy_paste`, `mosaic`), фиксированное число эпох и `last.pt`
  (выбор `best.pt` по внешнему фолду завышает оценку).
- Вывод с `augment=True`, затем ансамбль через `fuse_subs.py`.
- Не срезать слабые боксы: в AP они почти не вредят. Лимит — 30 на кадр.
- Боксы на корпусе робота (низ слева, щётка справа) — ложные; маски в `tools/nav_self_masks`.
