## Что использовано

- Общий сервер, YOLO11n-seg при 640 и YOLO11s-seg при 960. Веса для теста лежат в `~/Cleaner/audit/final/{det_all,big_f0}/weights/last.pt`. Их SHA-256 соответственно `c567bfa6dc07ec0b2e24c3b73a217c52bcc3203b77a5af22af653cd70309fa9d` и `0c6c840a502dd196f8b69d22fbae52fb1978a81182649097baf3c153387d9930`.
- Форма и материал используют обученные головы общего проекта, DFN-CLIP и SigLIP. Модель массы сопоставляет признаки текущего предмета с размеченными обучающими примерами, учитывая размер и признаки полой упаковки. На реальном кадре выбирается максимум один объект. Такой режим соответствует устройству реальной обучающей выборки.
- Вырезка проходит через локальную Qwen3-VL-4B-Instruct. Её ответ объединяется с вероятностями серверного классификатора, при смене материала или формы пересчитывается геометрическая оценка объёма. Для спорных предметов и особенно для содержимого закрытой тары ошибка массы остаётся большой.
- Дополнительный режим робота объединяет повторные наблюдения по визуальному сходству. При проигрывании четырёх проверочных групп 686 из 734 пар связанных размеченных наблюдений принадлежали одному предмету. Материал, массу и объём при новой встрече можно пересчитать для всех связанных кадров. При неверном объединении исправление распространится и на чужой предмет.

## Воспроизведение

На общем сервере нужны текущие файлы из `CleanerVolume/experiments`, штатное окружение `~/venv`, веса, кэши признаков обучающих объектов и геометрические строки проекта Cleaner. На Mac установлен mlx-vlm 0.8.0 в отдельном окружении ~/.local/share/astramis-vlm/venv. Для запуска нужны NumPy, Pillow, локальная копия датасета и скачанные веса Qwen3-VL-4B-Instruct в формате MLX. Использован снимок mlx-community/Qwen3-VL-4B-Instruct-4bit версии `2fd8dacbdb8f1e54b8c005f081ec5bf79c56376b`. Скрипт получает серверные предсказания по SSH, а обработку кадров визуально-языковой моделью выполняет на Mac. Из корня проекта:

```sh
HF_HUB_OFFLINE=1 TRANSFORMERS_OFFLINE=1 "$HOME/.local/share/astramis-vlm/venv/bin/python" CleanerVolume/experiments/build_final.py \
  --ssh '-i /Users/dmitry/.ssh/cleaner_shared_ed25519 -p 4107 cleaner@77.37.192.59' \
  --model "$HOME/.cache/astramis-models/qwen3-vl-4b-4bit" \
  --frozen-detections --dataset astramis_case/dataset --out submit/rebuilt.csv
```

Режим памяти находится в multiview.py и вызывается через опцию --robot-out серверного build_submission.py. Он использует серверные однокадровые предсказания до уточнения Qwen.

Источники внешних весов для описания решения: [Ultralytics](https://github.com/ultralytics/ultralytics), [DFN2B CLIP](https://huggingface.co/apple/DFN2B-CLIP-ViT-L-14), [SigLIP](https://huggingface.co/timm/ViT-B-16-SigLIP), [Qwen3-VL](https://huggingface.co/Qwen/Qwen3-VL-4B-Instruct), [конвертация для MLX](https://huggingface.co/mlx-community/Qwen3-VL-4B-Instruct-4bit).

Команда со снимками заново пересчитала атрибуты и ответы Qwen по всем 114 обнаружениям и воспроизвела итоговый SHA-256 побайтно. Снимки получены при двух успешных прогонах детекторов и проверяются по SHA-256. Полный повтор из весов на занятой видеокарте прервался из-за нехватки VRAM. После этого расчёт текстовых признаков перенесён на CPU. Полный повтор из весов с этой поправкой отдельно не замерен. Чтобы запустить детекторы заново, опустите --frozen-detections.
